Component Requirements
======================
.. requirement:definition:: MwLog.AvoidSignalProcessing

   The component shall not register any signal handler.

.. requirement:definition:: MwLog.FileDescriptorFlags

   The component shall set the FD_CLOEXEC (or O_CLOEXEC) flag on all the file descriptors
   it owns.

.. requirement:definition:: MwLog.DltVerboseMode

   mw::log shall implement DLT verbose mode. Generation of messages shall be done in
   DLT-conform format, allowing messages to be sent by Datarouter without additional reprocessing.

.. requirement:definition:: MwLog.AutosarLogTraceSpec

   mw::log shall implement "Specification of Log and Trace for Adaptive Platform". Release
   of specification used shall be in agreement with the rest of Adaptive AUTOSAR stack.

.. requirement:definition:: MwLog.InactiveLogStreamBehavior

   mw::log library shall not perform any useful activity if log level of LogStream object is
   insufficient for given context. LogStream object shall not generate serialized messages if the severity of
   the message does not allow it to be sent.

.. requirement:definition:: MwLog.SharedMemoryFilePermissions

   Logging shared-memory files shall have read-only posix file permission for group and
   others. The shared-memory file created by mw::log shall be read-only for group and others.

.. requirement:definition:: MwLog.ForwardToSystemLogger

   The system logger backend shall forward the logs to the native system logger mechanism.
   Under QNX, slogger2 shall be used.

.. requirement:definition:: MwLog.SystemBackendActivation

   The system logger backend shall be enabled if and only if the log mode contains
   "kSystem".

.. requirement:definition:: MwLog.LocalAllocationStrategy

   mw::log shall use local allocators to avoid using global heap. Global heap allocation
   (if any) shall be limited to the initialization phase of application lifecycle.

.. requirement:definition:: MwLog.BoundedLoopExecution

   mw::log shall not contain unbound loops or loops with unchecked exit conditions.

.. requirement:definition:: MwLog.TimeBoundedLocking

   mw::log shall be free of time-unbound locks and shall implement strategies to limit wait
   time. Time limit shall be defined based on requirements from functions on individual ECU. Mutual
   exclusion mechanisms shall include priority inversion protection.

.. requirement:definition:: MwLog.CrossLockingPrevention

   Cross-application and cross-thread dependencies shall be avoided. A thread logging in a
   loop shall not block other thread's execution.

.. requirement:definition:: MwLog.IndexAndSizeChecking

   Indices in data structures and sizes of data accessed or copied shall be checked for
   plausibility to avoid high runtime utilization through long iterations or data corruption.

.. requirement:definition:: MwLog.MemoryBoundChecking

   Memory boundaries shall be explicitly checked when writing to shared memory.
